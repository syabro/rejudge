# Rejudge: решения и текущее состояние

Обновлено: 5 августа 2026.

## Цель

Довести лендинг Rejudge до публичного выпуска на `rejudge.syabro.com`.

Готовый результат включает:

- понятный английский лендинг для нового пользователя;
- корректное отображение на desktop и mobile;
- инструкции, совпадающие с реальным поведением CLI и Pi extension;
- production deployment текущей версии;
- проверку английского и русского маршрутов на production.

## Текущие проблемы

### 1. Нужна настоящая asciinema-запись

Текущий demo — временная заглушка под будущую asciinema-запись. Нужно записать реальный запуск Rejudge, встроить запись в первый экран и заменить связанный с ней placeholder.

### 2. Текущая Astro-версия требует полного пользовательского прохода

Нужна проверка английской страницы глазами нового пользователя:

- понятен ли продукт по первому экрану;
- складывается ли последовательный рассказ от проблемы к решению и установке;
- работают ли навигация, внешние ссылки и Copy;
- сохраняется ли смысл SVG на desktop и mobile;
- помещаются ли тексты и элементы на узких экранах.

Русская страница проходит только layout-проверку.

## Принятые продуктовые решения

### Текст

- Английская версия полируется первой.
- Русский перевод сохраняется до отдельного полноценного review.
- Стиль текста: ELI18, прямой технический язык, одна мысль на абзац.
- Первый экран сразу объясняет назначение продукта.
- Детали внутренней работы идут после результата для пользователя.
- Формулировки ограничиваются реальным контрактом продукта.
- Термины используются последовательно по всей странице.

### Схема

- Семантика desktop-схемы согласована и реализована.
- Каждая модель передаёт Judge отдельный вывод.
- Judge может вернуть моделям дополнительные вопросы.
- Answer оформлен как выходной артефакт и визуально отделён от участников процесса.
- Run ID имеет вторичный вес.
- Mobile-схема использует вертикальную последовательность этапов.
- REL-072 вернул в mobile-схему feedback loop и добавил английское объяснение продолжения review по Run ID.

### Установка и конфигурация

- Основной пользовательский путь начинается с глобальной установки Rejudge.
- Один экземпляр Rejudge обслуживает standalone CLI и Pi extension.
- Основная конфигурация создаётся один раз глобально.
- Rejudge использует provider settings Pi.
- Команды Pi используют `/rejudge`.
- Инструкции лендинга соответствуют реальному install flow.

### Архитектура сайта

- Сайт является отдельным Astro-проектом внутри `site/`.
- Английский и русский маршруты используют общие компоненты и локализованный content.
- Компоненты, стили, зависимости и Astro config находятся внутри `site/`.
- Dev server запускается штатной командой из `site/`.

### Deployment

Cloudflare Pages project: `rejudge`.

Production-домен: `https://rejudge.syabro.com`.

Deployment выполняется из `site/`:

```bash
cd site
bun run deploy
```

После deployment проверяются:

- `https://rejudge.syabro.com/`;
- `https://rejudge.syabro.com/ru/`.

## Следующий порядок действий

1. Записать и встроить asciinema-demo реального запуска Rejudge.
2. Пройти английскую страницу на desktop и mobile как новый пользователь.
3. Проверить русский маршрут на layout.
4. Исправить найденные блокеры лендинга.
5. Собрать сайт из `site/`.
6. Загрузить `site/dist` в Cloudflare Pages через Wrangler.
7. Проверить `/` и `/ru/` на `rejudge.syabro.com`.
